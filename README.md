# toshi-api

The Protocol Buffers definitions of Toshi's APIs, and the Go and
TypeScript code generated from them.

| Package | What it is |
| --- | --- |
| `toshi.workspace.v1` | The Workspace API: workloads, executions, events, operations, projects, secrets, webhooks, artifacts and display sessions. This is the public contract for programs that drive Toshi. |
| `toshi.operator.v1` | The operator API, used by the dashboard and the `toshi` command line to run an installation: workspaces, hosts, runner jobs, tokens, usage, billing, alerts and storage providers. |
| `toshi.githubcore.v1` | The GitHub product's core API, for the product's adapter when it runs outside the control plane: the reads and writes it makes for a call the control plane passed to it, under that call's grant. |

The services are [Connect](https://connectrpc.com) services, served by the
Toshi control plane.

These files are authored in the Toshi core repository, beside the control
plane that implements them, and published here. Each publish replaces
this repository's tree in one commit, and a publish that raises
`VERSION` is tagged with that version. This repository takes no pull
requests.

## Layout

| Path | Contents |
| --- | --- |
| `proto/toshi/workspace/v1/`, `proto/toshi/operator/v1/`, `proto/toshi/githubcore/v1/` | The `.proto` files. |
| `workspacev1/`, `workspacev1/workspacev1connect/` | Go messages and Connect client and handler for `toshi.workspace.v1`. |
| `operatorv1/`, `operatorv1/operatorv1connect/` | The same for `toshi.operator.v1`. |
| `githubcorev1/`, `githubcorev1/githubcorev1connect/` | The same for `toshi.githubcore.v1`. |
| `ts/gen/toshi/` | TypeScript messages and service descriptors, generated by `protoc-gen-es` v2. |

## Go

The repository is the Go module `github.com/toshicloud/toshi-api`.
Depend on a tag; the newest one is on the
[releases page](https://github.com/toshicloud/toshi-api/releases):

```sh
go get github.com/toshicloud/toshi-api@<tag>
```

```go
import (
	"connectrpc.com/connect"

	workspacev1 "github.com/toshicloud/toshi-api/workspacev1"
	"github.com/toshicloud/toshi-api/workspacev1/workspacev1connect"
)

client := workspacev1connect.NewWorkloadServiceClient(httpClient, serverURL)
res, err := client.ListJobs(ctx, connect.NewRequest(&workspacev1.ListJobsRequest{
	Project:     "default",
	Environment: "production",
}))
```

A program should link one copy of the generated code. Protobuf for Go
refuses to start when two packages register the same `.proto` file, so
import these packages rather than generating a second copy from
`proto/`.

For a client with retries, waits and watches on top of the generated
code, see [toshi-go](https://github.com/toshicloud/toshi-go).

## TypeScript

`ts/gen/` holds the code `protoc-gen-es` v2 generates with
`target=ts,json_types=true`. It needs `@bufbuild/protobuf` 2, and a
client needs `@connectrpc/connect` 2 with a transport from
`@connectrpc/connect-web` or `@connectrpc/connect-node`. It is not
published as a package; copy it, or generate your own from `proto/`
with `buf generate`.

For a client package, see [toshi-ts](https://github.com/toshicloud/toshi-ts).

## Versioning

Versions follow [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html)
and are tagged `vMAJOR.MINOR.PATCH`, as Go modules expect. `VERSION`
holds the version of this tree. A change to `proto/` raises it.

While the major version is 0:

- an addition, a fix or a comment change bumps the patch version;
- a breaking change bumps the minor version, and the title of the pull
  request that makes it marks it with `!`, as in Conventional Commits
  (`feat!: ...`).

From v1.0.0, a breaking change never goes into an existing package. It
goes into a new one, `toshi.workspace.v2` or `toshi.operator.v2`, and a
`!` in the title does not allow it.

## Compatibility

Every change is checked with `buf breaking` before it is published,
against the branch it targets and against this repository's newest tag:
`toshi.workspace.v1` with the `FILE` rules, `toshi.operator.v1` and
`toshi.githubcore.v1` with the `WIRE_JSON` rules. A field or value that
goes away keeps its number and name reserved. While the newest tag's
major version is 0, a pull request whose title marks a breaking change
with `!` may break compatibility; no other failure is accepted. While
the major version is 0, the comparison with the newest tag counts only
what a pull request breaks beyond what its target branch already breaks.
From v1.0.0 there is no exception.

## Changing the protos

Changes are made in the Toshi core repository. The tools and their
versions are pinned in `mise.toml`.

```sh
mise install
scripts/generate.sh         # regenerates workspacev1/, operatorv1/, githubcorev1/ and ts/gen/
scripts/check-generated.sh  # fails if the committed code differs from a fresh generation
```

Commit a `.proto` change together with its generated code.
