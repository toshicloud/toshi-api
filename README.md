# toshi-api

The Protocol Buffers definitions of Toshi's APIs, and the Go and
TypeScript code generated from them.

| Package | What it is |
| --- | --- |
| `toshi.workspace.v1` | The Workspace API: workloads, executions, events, operations, projects, secrets, webhooks, artifacts and display sessions. This is the public contract for programs that drive Toshi. |
| `toshi.operator.v1` | The operator API, used by the dashboard and the `toshi` command line to run an installation: tenants, hosts, runner jobs, tokens, usage, billing, alerts and storage providers. |

The services are [Connect](https://connectrpc.com) services, served by the
Toshi control plane.

## Layout

| Path | Contents |
| --- | --- |
| `proto/toshi/workspace/v1/`, `proto/toshi/operator/v1/` | The `.proto` files. |
| `workspacev1/`, `workspacev1/workspacev1connect/` | Go messages and Connect client and handler for `toshi.workspace.v1`. |
| `operatorv1/`, `operatorv1/operatorv1connect/` | The same for `toshi.operator.v1`. |
| `ts/gen/toshi/` | TypeScript messages and service descriptors, generated by `protoc-gen-es` v2. |

## Go

The repository is the Go module `github.com/toshicloud/toshi-api`.
Depend on a tag; the newest one is on the
[releases page](https://github.com/toshicloud/toshi-api/releases):

```sh
go get github.com/toshicloud/toshi-api@<tag>
```

```go
import (
	"connectrpc.com/connect"

	workspacev1 "github.com/toshicloud/toshi-api/workspacev1"
	"github.com/toshicloud/toshi-api/workspacev1/workspacev1connect"
)

client := workspacev1connect.NewWorkspaceServiceClient(httpClient, serverURL)
res, err := client.ListWorkloads(ctx, connect.NewRequest(&workspacev1.ListWorkloadsRequest{
	Project:     "default",
	Environment: "production",
}))
```

A program should link one copy of the generated code. Protobuf for Go
refuses to start when two packages register the same `.proto` file, so
import these packages rather than generating a second copy from
`proto/`.

For a client with retries, waits and watches on top of the generated
code, see [toshi-go](https://github.com/toshicloud/toshi-go).

## TypeScript

`ts/gen/` holds the code `protoc-gen-es` v2 generates with
`target=ts,json_types=true`. It needs `@bufbuild/protobuf` 2, and a
client needs `@connectrpc/connect` 2 with a transport from
`@connectrpc/connect-web` or `@connectrpc/connect-node`. It is not
published as a package; copy it, or generate your own from `proto/`
with `buf generate`.

For a client package, see [toshi-ts](https://github.com/toshicloud/toshi-ts).

## Versioning

Versions follow [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html)
and are tagged `vMAJOR.MINOR.PATCH`, as Go modules expect.

While the major version is 0:

- an addition, a fix or a comment change bumps the patch version;
- a breaking change bumps the minor version, and its pull request title
  marks it with `!`, as in Conventional Commits (`feat!: ...`).

From v1.0.0, a breaking change never goes into an existing package. It
goes into a new one, `toshi.workspace.v2` or `toshi.operator.v2`, and a
`!` in the title does not allow it.

## Compatibility

Every pull request is checked with `buf breaking` against the branch it
targets and against the newest tag: `toshi.workspace.v1` with the `FILE`
rules, `toshi.operator.v1` with the `WIRE_JSON` rules. A field or value
that goes away keeps its number and name reserved. Before the first tag
and while the newest tag's major version is 0, a pull request whose
title marks a breaking change with `!` may break compatibility; no other
failure is accepted. While the major version is 0, the comparison with
the newest tag counts only what a pull request breaks beyond what its
target branch already breaks. From v1.0.0 there is no exception.

## Changing the protos

The tools and their versions are pinned in `mise.toml`.

```sh
mise install
scripts/generate.sh         # regenerates workspacev1/, operatorv1/ and ts/gen/
scripts/check-generated.sh  # fails if the committed code differs from a fresh generation
```

Commit a `.proto` change together with its generated code.
